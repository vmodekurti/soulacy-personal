Soulacy learns how your days work, what you have promised, and who is waiting on you — by asking, not by watching. It handles what it can and asks before the rest. Honest about setup: Soulacy runs on your own machine or a small VPS. Expect a terminal and about ten minutes. There is no hosted version to sign up for, which is the same reason nobody else holds your data.

Most assistants answer questions. This one keeps track.

Ask a chatbot the same thing twice and it has forgotten you in between. Soulacy keeps a structured picture of how your days actually go — your routine, the people who matter, what you owe and when — and every agent you run reads the same one.

it learns you, by asking

Not a chat history. It asks a few questions on your first day and records your answers in your words. A conversation in your browser: no phone, no sensors, nothing switched on.

it can also notice — optional

Add the iPhone app and allow a sense, and it keeps up on its own: a deadline moving, a Focus turning on, today not looking like a normal Tuesday. Skip it and Soulacy still works.

it stays quiet

“Nothing needs you today” is a real answer, and the system prefers it. An assistant that finds something urgent every morning is one you stop reading.

You ask. It builds.

Genie is the way in. Ask a question and you get an answer. Ask for something to be set up — “summarise overnight news every morning at seven” — and it gets built, by the same builder that sits behind Studio.

it asks, rather than guesses

No invented tools

The builder reads what is actually installed on your gateway. If you ask for email and no email channel is configured, you are told before it is built — not after it silently delivers nothing for a month.

what you get

A file, not a black box

A Soulacy agent is one YAML file anyone can read, review in a pull request, and roll back. You just did not have to write it. Studio is there when you want to edit it.

and you can stop it

Findable afterwards

Ask Genie what it has built for you, and pause or cancel any of it in the same conversation. Something you cannot find again is something you cannot stop.

Safety you cannot forget to add.

Every other option makes what an agent may do a matter of trust: code someone wrote, a canvas someone configured, or a service in someone else’s cloud. Here it is a property of the runtime. Agents fail closed, and every exception is a line you can read.

untrusted by default

A web page is evidence, not instructions

Anything fetched from outside — a page, a document, an MCP server’s reply — arrives wrapped as untrusted content and is scanned for injection before the model reads it. Text in a document cannot authorise a tool call.

privilege is declared

Two gates, both readable

OS-level tools need the server to permit them and the agent to declare them. On a managed platform where you have no shell of your own, the grant is refused outright — you cannot repair what you cannot reach.

attended and unattended differ

Nobody present means no

An action that would need your approval does not quietly approve itself because it happened at 3am on a schedule. Putting a privileged agent on a channel is a decision made on screen, by you.

evidence, not assertion

A reply is not proof

Agents are held to what tools actually returned. A failed delivery is a failure with a category, not a cheerful summary — twelve stable classifications, so “it did not send” always says why.

Try the injection sandbox above, or read the security model.

A briefing before you get up.

The iPhone app is optional, and it is the difference between an assistant that knows you and one that keeps up with you. It talks to your gateway, not to us.

Senses, off until you allow them

Location, calendar, reminders, motion, Health totals and Focus state reach only an agent that declares them, and only after you enable the matching toggle on the phone.

Approve on the lock screen

When an agent needs a decision, it asks there — with what it intends to do. Siri, Shortcuts, CarPlay and the share sheet all land in the same gateway.

One gateway, several phones

A household shares one server. Each phone signs in once and stays signed in; what it learns stays on your hardware.

self-hosted Personal

Run Personal on your infrastructure.

A gateway with an embedded web UI and a locally-issued API key. Configure your model provider and verify readiness before using it.

AWS · EC2

Deploy to AWS

guided setup

Creates an isolated network, encrypted Ubuntu VM, generated login secret, Postgres, Qdrant, automatic recovery, and an HTTPS endpoint. No inbound SSH.

Deploy to AWS ↗ Typically 8–12 minutes

After creation, use the direct Secrets Manager link in CloudFormation Outputs. Reveal api_key, sign in, then pair your iPhone from Mobile.

Microsoft Azure · VM

Deploy to Azure

guided setup

Creates a private virtual network, encrypted Ubuntu VM, static address, Postgres, Qdrant, and an Azure-hosted HTTPS endpoint. No inbound SSH.

Deploy to Azure ↗ Typically 8–15 minutes

Azure asks you to choose a 24+ character Soulacy login key. Save it, open the deployment URL, then pair your iPhone from Mobile.

Railway · Docker

Deploy to Railway

guided setup

Deploys the complete Personal gateway with HTTPS, persistent storage, health monitoring, and unique generated login and signing secrets. No configuration fields are required.

Deploy to Railway ↗

When it is online, open Railway Variables, reveal SOULACY_SERVER_API_KEY, and use it once to sign in. Then pair the iOS app from Soulacy’s Mobile screen.

One secure mobile handoff · every cloud

Sign in once. Pair your iPhone without copying the permanent key.

AWS generates the key in Secrets Manager, Azure asks you to choose it, and Railway generates it in Variables. After signing in to your new Soulacy URL, choose Mobile → Pair a device. The QR code expires in two minutes, works once, and gives the iOS app a scoped credential stored in Keychain.

Permanent key stays private
Never placed in a QR code, URL, or notification.
Render · Blueprint

Deploy to Render

one click

Creates a Docker web service with a persistent disk, production security profile, health monitoring, and generated login and session secrets.

Deploy to Render ↗

Render generates the Soulacy login key; save it from the service environment after provisioning.

Coolify · Your VPS

Deploy with Coolify

self-hosted

Runs the published Personal image on infrastructure you control, with durable workspace storage and explicit login and JWT secrets.

Coolify guide ↗

The repository includes a ready-to-import Compose file; Coolify provides the domain and TLS proxy.

or install on your own machine
macOS · Linux

One-line install

$ curl -fsSL https://soulacy.io/install.sh | bash

Installs soulacy + sy into ~/.local/bin. Boots with a printed API key.

Docker · production

Full stack

$ docker compose up

Postgres + Qdrant + gateway. Security posture defaults ON (intent-gate=deny, sandbox=on, profile=production).

Docker · lite

SQLite-only

$ docker compose -f docker-compose.lite.yml up

Embedded storage in one container, without a separate database service. Model access and optional tools still have requirements.

On a managed platform — Railway, Render, Fly, Cloud Run — you have no shell of your own, so Soulacy refuses to hand an agent one, and installs Skills and MCP servers through an approved path instead. What Soulacy is not.

Not a hosted assistant

There is nothing to sign up for. It runs on your laptop, a small VPS, or a Raspberry Pi, and what it learns about you stays there. About Personal →

Not a node editor

You build by asking, and what comes out is a readable file rather than boxes on a canvas. If you want drag-and-drop nodes, use n8n or Flowise.

Not another framework

Frameworks give you libraries and leave you to build and host the application. This is the application: UI, login, channels, schedules and memory already inside one binary.
